A second machine in the rail

One [[host]] block in attache.toml puts another machine’s tmux beside your local sessions — nothing installed over there, and the six features that matter (git, lazygit, the conversation rail, agent hooks, ⌘V, ⌘-click) follow the window to whichever machine it lives on.

1 · What a host is

Attaché’s one rule is that tmux owns everything and the app only renders what it is told. A remote host is the same rule over a longer wire: every command still goes to tmux — that tmux just runs on another machine, reached through ssh. The rail grows a machine tier only when a host is configured; with none, the app draws exactly what it always did.

Per host the app keeps one ssh master (authenticates once, every later connection multiplexes over it), one helper channel (a small shell loop, shipped as a command argument on every connect — it reads files, checks git, classifies paths so the app never mistakes a remote path for a local one), one control client per session, and one terminal surface per shown session running ssh -t … tmux attach.

2 · Connecting a machine, step by step

  1. Make ssh passwordless first. In a terminal, ssh yourhost must log in with no prompt (key or agent, or an alias in ~/.ssh/config). Every connection the app makes forbids prompts — an auth question printed into a control pipe corrupts the protocol — so password/2FA-only hosts do not work yet (#29).
  2. Add a block to ~/.config/attache.toml:
[[host]]
name = "mini"                          # what the rail calls it
ssh = "joey@192.168.8.68"              # or an ~/.ssh/config alias
tmux_path = "/opt/homebrew/bin/tmux"   # usually required, see below
# tmux_socket = ""                     # optional, same syntax as the global one
# git_tool_command = "lazygit"         # optional, what the Git tool runs there
# remote_open_command = ""             # optional, %h / %p, both pre-quoted
  1. Relaunch the app. Hosts are read once at launch; there is no hot reload yet (#28).
  2. Optional, for agent badges and transcripts on that machine: Settings → Behaviour → Agent status on remote hosts → Install. This writes the same hook script and status-line wrapper the local install writes, into that machine’s ~/.claude/, over ssh — with a timestamped backup, and it refuses to write if anything else edited the file meanwhile.
Why tmux_path is usually required. A non-interactive ssh shell has no Homebrew on its PATH, so bare tmux is “command not found” on most Macs. The app probes tmux -V on connect and, when it fails, the host row says exactly this and names the fix.

Requirements on the host

  • tmux ≥ 3.2 for the live decorations (activity dots, agent badges, git paths). Older tmux still gets sessions, windows and typing — the app says loudly that decorations are off. tmux 3.5’s different wire encoding is handled automatically.
  • git for the sidebar’s branch line; lazygit only if you use the Git tool there.
  • Nothing else. The helper is not an install.

4 · When it breaks

The host row is where trouble is said out loud. A grey dot is a healthy heading; yellow is connecting; red carries the ssh error in its tooltip, and clicking retries immediately instead of waiting out the backoff. A half-open connection — network died, nobody said so — is caught by a 10-second heartbeat.

5 · Answers to the first questions everyone hits

Scrolling in a remote shell moves through command history

Not an app bug: that host’s tmux has mouse off (a fresh tmux does). Without it, scroll wheels are translated into arrow keys inside full-screen programs, and at a shell prompt arrows mean history. Fix on the host: tmux set -g mouse on now, and set -g mouse on in its ~/.tmux.conf to keep it.

What the Install button on a host row does

Agents publish their state and transcript path through hooks in their own machine’s ~/.claude/settings.json — so a remote agent needs the hooks installed remotely, once per machine. The button does exactly what the local install does, over ssh: writes two short readable scripts, appends our entries (other tools’ entries untouched), backs the file up first, and refuses to write if the file changed under it. Remove undoes it and restores what was there, unknown fields included.

Two blocks for one machine

Legal — two [[host]] blocks may point at the same destination with different tmux sockets. They share one ssh master.

6 · Not there yet

  • No Settings UI to add or edit hosts, and no hot reload — TOML by hand, then relaunch (#28).
  • Password / 2FA ssh auth (#29).
  • Dropping files into remote windows (#30).
  • Linux hosts are written for but not yet verified against; large-transcript first fetch is uncapped; startup target is local-only (#31).
